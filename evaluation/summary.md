# Evaluation Summary

## Benchmark

- **Dataset size:** 20 questions (hand-curated golden dataset)
- **Evaluation framework:** RAGAS v0.4.3
- **Total RAGAS jobs:** 80 (20 questions × 4 metrics)
- **Total wall-clock time:** ~1 hour 47 minutes
- **Abstention rate:** 10% (2 questions intentionally unanswerable)

---

## Headline Metrics

| Metric | Score |
|---|---|
| **Mean Faithfulness** | **0.911** *(18 computable questions — see note below)* |
| Answer Relevancy | 0.660 |
| Context Precision | 0.821 |
| Context Recall | 0.850 |
| Context Recall (Answerable) | 0.895 |

**Faithfulness note:** Two questions (Q10 and Q11) returned `NaN` faithfulness. Post-hoc log analysis confirmed this was a metric-infrastructure failure — the judge model emitted an HTTP 400 `json_validate_failed` error when decomposing unusually long, multi-bulleted answers into structured JSON claim schemas. This is not a hallucination event; both answers were substantively correct. The mean of 0.911 excludes these two rows.

## Bottleneck Distribution

| Bottleneck Type | Count | Description |
|---|---|---|
| **NO_BOTTLENECK** | **17** | Pipeline passed — retrieval and generation both succeeded |
| RETRIEVAL_RECALL_BOTTLENECK | 1 | Q16 — correct chunk was not retrieved |
| RETRIEVAL_PRECISION_BOTTLENECK | 1 | Q20 — context window flooded with redundant chunks |
| GENERATOR_BOTTLENECK | 1 | Q17 — correct context retrieved, but answer incomplete |

> The automated classifier reports 16 NO_BOTTLENECK. The corrected count is **17**, because Q01 is a correct, intentional abstention to a query explicitly marked `UNANSWERABLE` in the golden dataset. The classifier misidentifies this as a recall miss.

## Judge Model Methodology

The evaluation uses a **distinct, high-capability judge model** (`openai/gpt-oss-120b`) to score answers generated by the production model (`llama-3.1-8b-instant`). This separation prevents self-grading bias, where a model would systematically over-award faithfulness scores to its own paraphrases. The judge was accessed via the Groq inference API. See [methodology.md](../methodology.md) for full details.
